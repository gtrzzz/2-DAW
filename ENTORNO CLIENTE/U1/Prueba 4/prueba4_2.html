Ejercicio 2: cálculo de diferencia temporal entre dos fechas

RA1 – CE 1.d · Ventajas de la programación de guiones: agilidad y reutilización de tipos nativos del anfitrión (Date) frente a tener que implementar la aritmética temporal a mano.

Enunciado

Implementar la función calcularDiasDiferencia(fechaInicio, fechaFin) que reciba dos cadenas de texto en formato YYYY-MM-DD y devuelva el número entero de días transcurridos entre ambas fechas, usando la diferencia en milisegundos con .getTime() y redondeando con Math.round() para evitar inconsistencias con los cambios de horario de verano/invierno.

Implementación

const MS_POR_DIA = 86400000; // 24 h × 60 min × 60 s × 1000 ms

function calcularDiasDiferencia(fechaInicio, fechaFin) {
  // Se concatena "T00:00:00" para forzar la interpretación en HORA LOCAL.
  // Si se hiciera new Date("2026-03-28") el motor lo leería como medianoche UTC.
  const inicio = new Date(fechaInicio + "T00:00:00");
  const fin = new Date(fechaFin + "T00:00:00");

  if (isNaN(inicio.getTime()) || isNaN(fin.getTime())) {
    return NaN;
  }

  return Math.round((fin.getTime() - inicio.getTime()) / MS_POR_DIA);
}

Por qué hay que redondear y no truncar

El 29 de marzo de 2026 a las 02:00 la hora local salta de 02:00 a 03:00 (comienza el horario de verano). Ese día no tiene 24 horas reales, tiene 23. Por eso la diferencia en milisegundos entre dos medianoche locales que cruzan ese cambio no es múltiplo exacto de 86.400.000.

Comprobado con el ejemplo del probador (27 de marzo -> 31 de marzo de 2026):

Variante Diferencia en ms Math.round() Math.floor() Correcto
Hora local + Math.round() 342.000.000 4 días 3 días Sí (con round)
Hora local + Math.floor() 342.000.000 4 días 3 días No: trunca y pierde un día

342.000.000 ms son 3,958 días: truncar se queda con 3, pero entre el 27 y el 31 de marzo hay 4 días de calendario. Math.round() absorbe el desfase de una hora y devuelve el valor correcto.

Conclusión: la combinación segura es interpretar en hora local con T00:00:00 (así se cuentan días de calendario) y redondear con Math.round() (así se absorbe el cambio horario). Math.floor() solo es válido si la resta da un múltiplo exacto de 86.400.000, cosa que no ocurre al cruzar un cambio de horario.
