Ejercicio 7: laboratorio de errores en tiempo de ejecución

RA1 – CE 1.d · Desventaja de la programación de guiones: los errores se detectan en tiempo de ejecución y no antes, lo que obliga a un plan de pruebas mucho más exhaustivo.

Enunciado

Crear un script sencillo en un archivo calculo.js que intente ejecutar una operación matemática con una variable no declarada previamente. Comprobar en el navegador qué sucede: observar cómo las líneas anteriores a la instrucción fallida se ejecutan con normalidad y cómo el intérprete se detiene únicamente al alcanzar el fallo en tiempo de ejecución, comprobando en la consola el error emitido.

Código de ./js/calculo.js

console.log("--- calculo.js: inicio de la ejecucion ---");

const precio = 25;
const iva = 0.21;

console.log("1. precio declarado:", precio);
console.log("2. iva declarado:", iva);

const subtotal = precio * 3;
console.log("3. Subtotal (precio * 3):", subtotal);

console.log("4. A partir de aqui se intenta usar una variable NO declarada...");
const total = subtotal - descuento; // <-- ReferenceError: descuento is not defined

console.log("5. Esta linea no llega a mostrarse porque el script ya se detuvo.");
console.log("6. Total con descuento:", total);

Resultado esperado al abrir la página

Con F12 abierto en la pestaña Consola, la salida es exactamente esta, en este orden: 

--- calculo.js: inicio de la ejecucion ---
1. precio declarado: 25
2. iva declarado: 0.21
3. Subtotal (precio * 3): 75
4. A partir de aqui se intenta usar una variable NO declarada...
Uncaught ReferenceError: descuento is not defined
    at calculo.js:25:32

Las trazas 5 y 6 no aparecen. Eso es la prueba de que el intérprete se detiene en el momento exacto del fallo.

Qué demuestra este experimento

Aspecto Lenguaje tradicional (Java, C++, C#) Lenguaje de script (JavaScript)
Cuándo se detecta el error En compilación, antes de ejecutar nada En ejecución, al alcanzar la línea
Qué ocurre con el programa El binario no llega a generarse Las líneas anteriores sí se ejecutan
Consecuencia Un error de nombre nunca llega al usuario Un error en una rama poco transitada puede llegar al usuario final
Plan de pruebas El compilador cubre la mayoría de errores Hay que probar todas las ramas a mano

La página, pese al error, se muestra entera

Este es el segundo aprendizaje de la práctica. El ReferenceError detiene el fichero calculo.js, no el documento. El navegador continúa interpretando el HTML, aplica el CSS y dibuja la página con normalidad, y los demás <script> del proyecto se ejecutan igualmente. Estás leyendo precisamente esa página ahora mismo, con un script roto cargado en el <head>.

Esto explica por qué un sitio web puede verse "medio roto" en lugar de mostrar un error general: cada script es una unidad de ejecución independiente y un fallo aislado solo afecta a su propio bloque de código.

Cómo evitarlo

// 1. Declarar la variable (la solución directa)
const descuento = 10;
const total = subtotal - descuento;

// 2. Comprobar antes de usarla
const total = typeof descuento !== "undefined" ? subtotal - descuento : subtotal;

// 3. Declarar al principio de la funcion todas las variables (buena practica)
function calcular() {
  const precio = 25;
  const iva = 0.21;
  const descuento = 10;   // <- declarada, sin sorpresas
  return precio * 3 - descuento;
}

// 4. En modo estricto, el error se detecta antes y no se crean globales por error
//    (se activa con "use strict" al principio del fichero o del bloque)

Variante: "use strict"

En los scripts normales, si en lugar de leer una variable se le asigna sin declararla, JavaScript crea una global silenciosamente. Con "use strict" eso deja de ocurrir y se lanza un ReferenceError en el momento, que es exactamente lo que se busca en un lenguaje compilado. Botón para comprobarlo:
