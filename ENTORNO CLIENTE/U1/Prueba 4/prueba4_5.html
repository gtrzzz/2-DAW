Ejercicio 5: ¿en qué se diferencia técnicamente JavaScript de Java?

RA1 – CE 1.d · Clasificación de los lenguajes de programación de clientes Web y comparación con la programación tradicional.

Enunciado

¿En qué se diferencia técnicamente JavaScript de Java?

Resumen

Java y JavaScript no tienen ninguna relación técnica. El nombre común se debe a una decisión comercial de 1995: Sun Microsystems quería transmitir que su lenguaje tradicional, Java, era el lenguaje de moda para internet, y el nuevo lenguaje de Netscape, pensado inicialmente como LiveScript, se renombró a JavaScript para aprovechar esa publicidad. ECMA International lo estandarizó en 1996 y, para evitar problemas legales de marca, lo rebautizó ECMAScript, nombre que sigue siendo el nombre oficial del lenguaje. Ninguno de los dos deriva del otro.

Comparativa técnica completa

Clasificación (CE 1.d) Lenguaje de programación tradicional Lenguaje de script / guiones
Proceso de traducción Compilado a bytecode (.class) y ejecutado por la JVM Interpretado por el motor del navegador (o por Node.js) sin compilación previa
Sistema anfitrión (host) La máquina virtual Java (JVM), instalada en el sistema El navegador web (o el intérprete de Node.js)

Nombre oficial Java (JLS, Java Language Specification) ECMAScript (norma ECMA-262)
Ámbito de uso Aplicaciones de escritorio, Android, backend, sistemas empresariales Programación de clientes Web en el navegador y, con Node.js, servidor
Detección de errores En compilación: si hay un error de tipo, el .class no se genera En tiempo de ejecución (runtime), línea a línea

El mismo resultado, philosophies opuestas

Declarar e inicializar el número 42 en cada lenguaje:

// JAVA: compilado a bytecode, tipo declarado de forma explicita
public class Main {
    public static void main(String[] args) {
        int numero = 42;              // el tipo forma parte de la declaracion
        System.out.println(numero);  // 42
    }
}
// JAVASCRIPT: interpretado, el tipo se deduce del valor
let numero = 42;
console.log(numero);   // 42
numero = "cuarenta y dos";  // permitido: ahora es una cadena
console.log(numero + 1);    // "cuarenta y dos1" (concatenacion, no suma)

Esa última línea es la demostración más clara de la diferencia de tipado: en Java el compilador rechazaría la asignación (incompatible types), y en JavaScript se acepta y produce una concatenación silenciosa. Es la contrapartida de la flexibilidad del lenguaje dinámico.

Por qué importa la diferencia para el RA1

Elegir JavaScript para el cliente web no es una cuestión de gusto, es una imposibilidad técnica: el navegador solo admite HTML, CSS y JavaScript. No se puede ejecutar bytecode de la JVM en el navegador sin instalar una máquina virtual completa, y JavaScript es, por definición, el lenguaje de script que se acopla al documento HTML mediante la etiqueta <script> y se ejecuta en ese entorno anfitrión.

En la práctica, Java se usa en el servidor (Spring, Jakarta) y JavaScript en el cliente, y ambos se comunican por HTTP con JSON. Esa separación es la arquitectura cliente/servidor clásica reaplicada a la web moderna.

Demostración interactiva del tipado dinámico
