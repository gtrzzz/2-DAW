Apartado 1.2 con estructura profesional de carpetas

RA1 – CE 1.a · Capacidades y mecanismos de ejecución de código de los navegadores Web. Esta carpeta es la versión reorganizada de los ejercicios de Prueba 2/: en lugar de escribir el JavaScript dentro de los atributos onclick y de bloques <script> del propio HTML, toda la lógica se ha trasladado a ficheros .js externos.

Por qué se ha hecho esta copia

El apartado 1.5 pide rehacer los ejercicios de 1.2 y 1.4 con la estructura profesional de carpetas. Los ficheros originales de Prueba 2/ se conservan intactos porque son la versión con el enfoque embebido, que es exactamente el que el apartado 1.5 critica y sirve de referencia para comparar. Esta carpeta profesional/ es la versión equivalente con ficheros externos, y permite comprobar en la pestaña Network que cada .js se sirve con estado 200 OK.

Comparación de enfoques: embebido frente a externo

Aspecto Original (Prueba 2/) Reorganizado (profesional/)
Ubicación del JavaScript Atributos onclick y bloques <script> del HTML Ficheros .js en la carpeta js/
Registro de eventos Atributo onclick en línea addEventListener() desde el .js
Estilos En línea o sin estilar Hoja compartida css/estilos.css
Variables var dentro de los atributos const y let en el .js
Comparaciones == (no estricta) === (estricta)
Memoria caché No aplicable: el código va dentro del HTML Los .js y el .css se cachean
Reutilización Hay que copiar el código en cada página Un .js enlazado desde todas las páginas

Comprobación en la pestaña Network (Red)

Con F12 abierto en Network, cada página de esta carpeta debe solicitar css/estilos.css y su fichero .js con estado 200 OK. Al navegar de una página a otra se observará que el .css y los .js ya no se vuelven a descargar (aparecen como from disk cache o from memory cache), lo que demuestra la primera ventaja de los ficheros externos.

Si abres los archivos con doble clic (file://), la pestaña Network puede no mostrar el código de estado. Para comprobar el 200 OK real hay que servir la carpeta con un servidor local, por ejemplo con la extensión Live Server de Visual Studio Code.
