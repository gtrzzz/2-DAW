Actividad 2: código JavaScript embebido dentro del HTML

RA1 – CE 1.e · El segundo mecanismo de integración: bloques <script> sin src, escritos entre las líneas del propio marcado.

Comprobación

Al cargar la página aparece el cuadro de alerta con el texto Hola aunque en esta variante no hay ningún fichero .js externo: el código está escrito dentro del propio HTML. Pulsa "Aceptar" para continuar.

Justo debajo, el segundo botón de la demostración sí es externo, para poder comparar en la misma página los dos mecanismos y comprobar que el resultado visual es idéntico.

Código completo de la página

<!DOCTYPE html>
<html>
<head>
  <title>Myfpschool</title>
  <script>
    // Se declara la funcion dentro de la cabecera head
    function diAlgo() {
      alert("Hola");
    }
  </script>
</head>
<body>
  <!-- Se ejecuta la funcion en el cuerpo del documento body -->
  <script>
    diAlgo();
  </script>
</body>
</html>

Comparación de los dos mecanismos

Los dos botones producen el mismo cuadro de texto. Lo que cambia no es el resultado, sino la organización del código:

Aspecto Código embebido Código externo (recomendado)
Número de archivos12 o más
Resultado visualIdénticoIdéntico
MantenimientoDifícil si hay muchos bloquesFácil: un archivo por función
Memoria cachéNo se puede cachear (va dentro del HTML)Se cachea el .js
ReutilizaciónHay que copiar el bloque en cada páginaSe enlaza y se reutiliza
Colaboración en equipoDiseñador y programador se pisanCada uno trabaja en su archivo
Legibilidad del HTMLEl marcado se mezcla con la lógicaEl HTML queda limpio
Cuándo usarloCódigo mínimo de una sola página que no cambiaráCualquier proyecto real

Características y desventajas del enfoque embebido

  • Mismo resultado visual. Tanto el enfoque embebido como el externo provocan exactamente el mismo efecto ante el usuario: aquí, los dos, un cuadro emergente con el saludo.
  • Dificultad de mantenimiento. Diseminar bloques <script> desordenados por el <head> y el <body> convierte el código en un bloque difícil de depurar, entender y mantener a largo plazo.
  • Criterio de uso excepcional. Solo se justifica cuando las líneas de código son mínimas, específicas de una sola página y no se van a modificar prácticamente nunca.
